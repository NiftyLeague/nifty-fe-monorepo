# M4.0 — Shared code, style, and configuration inventory

Status: inventory complete; the `apps/docs` deep-dive ships with it. Cross-app verdicts are scoped follow-ups for M4.2 and M4.4 and are not executed here.

This record enumerates every module, stylesheet, and build/deploy setting that the four web surfaces currently implement more than once, and assigns each one a single verdict. It is deliberately descriptive about what is _not_ shared: several of the duplicates named in M4.0 are only superficially alike, and merging them would change behavior rather than remove duplication.

## Method

Survey of `apps/web`, `apps/smashers`, `apps/docs`, `apps/app` plus `packages/ui`, reading each duplicated module in full and diffing implementations against each other and against the shared package. Verdicts were checked against call sites, the contract tests in `test/contract/`, and `git log` for the pre-migration shape.

## Decision vocabulary

| Verdict    | Meaning                                                                                                                      |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **keep**   | The duplicate is real but intentional per-app behavior. Merging would couple apps to a shared default they should not share. |
| **share**  | One implementation belongs in a shared package, with app-specific inputs passed in.                                          |
| **inline** | The code stays app-local; only a smaller pure core is shared.                                                                |
| **remove** | The copy is dead or unreachable and should be deleted rather than shared.                                                    |

## Drift findings

Defects found while diffing. Each was resolved or explicitly carried forward in the follow-ups below; the status line says which.

- **D1 — web subheader font is unreachable. — FIXED** (#1893). The variable now comes from the shared stylesheet, and `.heading-look-4` resolves to `NL Press Start 2P` with the font actually loaded, where it previously resolved to the body font and was never even requested. Original finding: `apps/web/src/layouts/Base.astro:20` declares `--font-press-start-2p`, but the shared theme consumes `--font-press-start` (`packages/ui/src/styles/01_tailwind.theme.css:79`) and `apps/web/src/styles/app.css:16` maps `--subheader-font` onto that `--special-font` chain. The pre-migration shared helper declared `--font-press-start` (`packages/ui/src/lib/fonts/special.ts`, removed in #1870), so this is a rename introduced by the migration: the substitution now fails and `font-family: var(--font-subheader)` (app.css:62, 70, 78) resolves to nothing, falling back to the inherited body font. `test/contract/font-loading.test.ts:86` currently pins the drifted name.
- **D2 — smashers is the only app with metric-override fallbacks. — RESOLVED AS A NON-GOAL** (#1893). Measuring the fallbacks showed their advance widths are faithful for IBM Plex Sans (+0.6%) and Lilita One (+0.6%) but not for Nexa Rust (+2.2%, enough to rewrap a heading and add 0.0336 CLS to the app's games page) or Press Start 2P (+140%). The shared stylesheet now declares the real faces and their variables; the fallback layer is an app-local, measured decision that only smashers carries. Original finding: and web is the only app whose `@font-face` family does not match its custom-property name. Both are absorbed by the shared fonts stylesheet verdict.
- **D3 — docs' GTM idle timeout comment is wrong. — FIXED** (#1892): the comment now states the scheduling is docs-specific. Original finding: `apps/docs/src/components/Analytics.astro:35` sets `IDLE_TIMEOUT_MS = 1500` and describes it as matching "the shared deferred-activation idle timeout", which is a 5000 ms delay followed by an inner 1000 ms idle callback (`packages/ui/src/lib/deferred-activation.ts:2`). The value is docs-specific; only the comment is inaccurate.
- **D4 — three different analytics gates. — OPEN**, carried by #1889 for an analytics owner: the modules share the schedule and the loader, but each keeps its own gate. Original finding: Web gates GTM on `PUBLIC_TELEMETRY !== 'false' && environment === 'production'`, smashers on `documentElement.dataset.analytics !== 'false'`, docs and app load unconditionally. Unifying them is an analytics-policy decision, not a refactor.
- **D5 — web's `Link` shim carries five unreachable compat props plus an object-`href` branch** used by no caller (see the runtime table). — FIXED (#1894): the shim is deleted and both pages render plain anchors, with the built pages byte-identical.

## What M4.0 executes

The `apps/docs` deep-dive, verified against the docs migration's parity method:

1. Extract the framework-neutral GTM DOM loader into `packages/ui` and adopt it in `apps/docs/src/components/Analytics.astro`, which keeps its own scheduling. Also refactor the shared React boundary onto the same function so there is one loader, not two.
2. Delete docs' unused `@nl/ui/custom/optimized-image` alias.
3. Add `@nl/astro-config` with the shared Astro app defaults and adopt it in `apps/docs/astro.config.mjs`.

### Verification

The docs build is byte-reproducible, which makes the dist tree an exact parity instrument: two consecutive builds of the unchanged app produced 10,959 identical file hashes. The refactor was verified by building the pre-change and post-change trees and diffing them file by file.

| Check                       | Result                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route parity                | 55 pages both sides; `sitemap-0.xml` byte-identical                                                                                               |
| Dist diff                   | 55 HTML files differ only inside the inline GTM module, plus that module's sourcemap; all other 10,903 files byte-identical                       |
| Transfer delta              | +65 bytes per page; JavaScript bytes, CSS bytes, and request count unchanged (measured in Chrome over the local build, 5 runs)                    |
| Lighthouse (mobile, 3 runs) | score 98 → 98, LCP 2105 → 2104 ms, CLS 0.0000 both, requests 19 both                                                                              |
| Runtime behavior in Chrome  | one `#_next-gtm` script with the same `src` and `async`, the same `gtm.js` data-layer start event, no console errors — identical before and after |
